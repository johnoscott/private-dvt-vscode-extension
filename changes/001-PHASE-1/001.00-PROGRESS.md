## What was built

### Core Libraries (1,402 lines of TypeScript across 17 source files)

#### 1. Directed Graph Library (`src/core/graph/`)
A pure, zero-dependency TypeScript DAG library. No VSCode APIs — usable in extension, webview, CLI, and tests.

- Node/edge CRUD with typed metadata
- BFS/DFS traversal with configurable depth limits
- `ancestors(id, depth?)` / `descendants(id, depth?)` — upstream/downstream discovery
- `shortestPath(from, to)` — BFS shortest path
- `allPaths(from, to, maxPaths?)` — all paths via DFS with backtracking
- Topological sort (Kahn's algorithm) with cycle detection
- Induced subgraph extraction
- Full JSON serialization/deserialization (for webview transport and caching)

#### 2. dbt Ref Extractor (`src/core/dbt/extract-refs.ts`)
Regex-based extraction of `{{ ref('model') }}` and `{{ source('src', 'table') }}` from raw dbt SQL templates. No Jinja rendering needed. Handles single/double quotes and whitespace variations.

#### 3. dbt Project Parser (`src/core/dbt/dbt-project.ts`)
Reads a dbt project directly from the filesystem — no Python, no manifest.json, no dbt CLI.

- Parses `dbt_project.yml` → project config (name, model-paths, seed-paths, etc.)
- Walks model-paths → discovers all `.sql` files → builds model map
- Walks YAML files → discovers `sources:` definitions
- `refsFor(model)` → all ref/source dependencies for a model
- `dependencyMap()` → model name → dependency model names

Performance: parses 600+ model project (dbt_infomart) including 2.5MB YAML files in ~1.8 seconds.

#### 4. dbt Project Discovery (`src/core/dbt/find-projects.ts`)
- `findDbtProjectsInDir(dir, maxDepth?)` — recursively searches for `dbt_project.yml`, stops descending once a project root is found
- `findProjectRoot(filePath)` — walks up from any file to find its nearest dbt project root
- Skips `node_modules`, `.git`, `target`, `dbt_packages`, etc.

#### 5. DVT Manifest (`src/core/dbt/manifest.ts`)
Lightweight alternative to dbt's manifest.json. Built entirely from file parsing.

- `DvtManifest` type: project metadata, nodes (models), sources, edges, stats
- `buildManifest(project)` → serializable manifest
- `manifestToGraph(manifest)` → `DirectedGraph` for graph operations
- JSON round-trips cleanly (can cache to `.dvt/manifest.json`)
- Includes: model name, file path, relative path, folder grouping, refs/sources

#### 6. SQL Utilities (`src/core/sql/`)
Bonus modules (not on critical path, but useful):
- `stripJinja(sql)` — replaces `ref()`/`source()` with placeholder table names, removes Jinja blocks/comments
- `extractTableRefs(sql)` — regex-based extraction of table references from FROM/JOIN clauses with CTE awareness

#### 7. Lineage Engine (`src/core/lineage/`)
Provider abstraction for pluggable lineage sources:
- `LineageProvider` interface with `discover()` and `dependencies()` methods
- `DbtLineageProvider` — wraps dbt project parser
- `LineageEngine` — registers providers, builds unified `DirectedGraph`

### VSCode Extension (`src/extension.ts`)

#### Multi-Project Support
- Auto-discovers all dbt projects in workspace by walking folder tree for `dbt_project.yml`
- Tracks which project the active editor file belongs to (walk-up to `dbt_project.yml`)
- Status bar shows active project context, updates when switching files
- All commands work across multiple projects

#### Commands (5)
| Command | Description |
|---|---|
| `DVT: Show Manifest` | Dumps models, folders, dependencies to Output panel |
| `DVT: Show Lineage Summary` | Graph stats, root/leaf nodes, topological build order |
| `DVT: Inspect Model` | Quick-pick search → shows upstream/downstream lineage, opens file |
| `DVT: Rebuild Manifest` | Re-parses all projects (also auto-triggers on file changes) |
| `DVT: Select Project` | Switch between projects in multi-project workspaces |

#### File Watchers
- Watches `**/*.{sql,yml,yaml}` in each project
- Debounced 1-second rebuild on change/create/delete
- Status bar auto-updates

#### Jinja-SQL Language
- Bundled TextMate grammar (`syntaxes/jinja-sql.tmLanguage.json`)
- SQL keywords, functions, types, operators
- Jinja2 blocks (`{% %}`), expressions (`{{ }}`), comments (`{# #}`)
- dbt-specific functions highlighted: `ref`, `source`, `config`, `var`, `env_var`
- Language configuration: bracket matching, comment toggling, folding, indentation
- Auto-associates `.sql` files in dbt project directories

## Architecture Decisions Made

1. **dbt-first, ref()-driven**: The graph is built from `{{ ref() }}` regex extraction, not SQL parsing. This is the 80/20 — `ref()` is the entire contract for dbt lineage.

2. **No Python bridge**: dbt project parsed directly from files. dbt CLI subprocess (optional) for run/test/build — not needed for lineage.

3. **Zero extension dependencies**: Jinja-SQL grammar bundled, no jinjahtml or ms-python required.

4. **Multi-project by default**: Extension walks workspace folders for `dbt_project.yml`. Any file's project is found by walking up. Works with mono-repos, multi-project workspaces, and single projects.

5. **DVT Manifest over dbt manifest**: Our own lightweight format, built from file parsing. JSON-serializable for caching. Convertible to a `DirectedGraph` for operations.

6. **Icon theme approach**: SVG-based icon theme (not font glyphs) — simpler, no tooling overhead, easily customizable.
