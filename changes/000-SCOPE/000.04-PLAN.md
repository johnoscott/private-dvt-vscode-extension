# Implementation Plan

## Approach: dbt-first, ref()-driven

The simplest useful graph comes from:
1. Read `dbt_project.yml` → get project name, model-paths
2. Walk model-paths for `.sql` files → each file = one model node
3. Regex-search each file for `{{ ref('...') }}` and `{{ source('...', '...') }}` → edges
4. Build a `DirectedGraph` from that → our own lightweight "manifest"
5. Visualize it

No SQL parsing needed for the initial graph. No manifest.json needed. No Python needed.
The `{{ ref() }}` pattern is the entire contract for dbt lineage.

## Phase 2: Graph Visualization

### 2.1 Lineage Graph Webview

- [ ] React app in `src/webview/lineage/`
- [ ] Message protocol: extension ↔ webview
- [ ] Canvas-based DAG renderer (Canvas2D)
- [ ] Dagre layout for automatic positioning
- [ ] Node rendering: name, type badge (model/source/seed)
- [ ] Edge rendering: directed arrows
- [ ] Interactions: pan, zoom, click-select, double-click-open-file
- [ ] Expand/collapse: click to show upstream/downstream N levels
- [ ] Search: find model by name
- [ ] Webview panel host in extension

### 2.2 Extension Activation

- [ ] Activate on `workspaceContains:**/dbt_project.yml`
- [ ] Parse project on activation → build graph
- [ ] File watchers: rebuild on `.sql` or `.yml` file changes
- [ ] Command: "DVT: Show Lineage Graph"
- [ ] Status bar: project name + model count

### 2.3 Go-to-Definition

- [ ] Cursor on `ref('model')` → jump to model `.sql` file
- [ ] Cursor on `source('src', 'table')` → jump to source YAML definition

### 2.4 Hover

- [ ] Hover on `ref()` → show model description, upstream/downstream count
- [ ] Hover on `source()` → show source description, schema
