# Architecture

## Core Design Principle: SQL Lineage Abstraction

dbt is one method of expressing data transformations. Pure SQL is another. The extension is built on an abstraction where lineage can be derived from multiple sources, unified into a single graph.

```
┌─────────────────────────────────────────────┐
│           VSCode Extension (UI Layer)        │
│  Lineage Graph │ Docs Panel │ Editor Integ.  │
└──────────┬──────────────────────────────────┘
           │
┌──────────▼──────────────────────────────────┐
│         Lineage Engine (TypeScript)          │
│                                              │
│  ┌──────────────┐  ┌─────────────────────┐  │
│  │ SQL Provider  │  │  dbt Provider       │  │
│  │ (AST parse)   │  │ (project parse)     │  │
```

## Module Structure

### `src/core/graph/` — Pure DAG Library

A standalone, zero-dependency directed graph library. No VSCode APIs — can be used in CLI, tests, or webview.

**Capabilities:**
- Add/remove nodes and edges with typed metadata
- Topological sort
- Ancestor and descendant traversal (with depth limits)
- Shortest path between two nodes
- All paths between two nodes
- Subgraph extraction (N-hop neighborhood)
- Cycle detection
- Connected component identification
- Serializable to/from JSON (for webview transport and CLI interop)

**Data model:**
```typescript
interface GraphNode<T = unknown> {
  id: string;
  data: T;
}

interface GraphEdge<T = unknown> {
  source: string;
  target: string;
  data: T;
}

class DirectedGraph<N = unknown, E = unknown> {
  addNode(id: string, data: N): void;
  addEdge(source: string, target: string, data: E): void;
  ancestors(id: string, maxDepth?: number): string[];
  descendants(id: string, maxDepth?: number): string[];
  shortestPath(from: string, to: string): string[] | null;
  allPaths(from: string, to: string): string[][];
  topologicalSort(): string[];
  subgraph(nodeIds: Set<string>): DirectedGraph<N, E>;
  toJSON(): SerializedGraph<N, E>;
  static fromJSON<N, E>(data: SerializedGraph<N, E>): DirectedGraph<N, E>;
}
```

### `src/core/sql/` — SQL Parser

A TypeScript SQL parser focused on lineage extraction. Not a full SQL transpiler — purpose-built for identifying table references, column references, aliases, and data flow.

**Capabilities:**
- Parse SELECT, FROM, JOIN, WHERE, GROUP BY, HAVING, ORDER BY
- CTE (WITH clause) resolution
- Subquery handling
- UNION/INTERSECT/EXCEPT
- Table and column alias tracking
- Dialect-aware parsing (BigQuery, Snowflake, Postgres, DuckDB, Redshift)
- Extract: source tables, output columns, column-to-source-column mappings

**Design:**
- Tokenizer → Parser → AST → Lineage Extractor
- The AST is an intermediate representation; the lineage extractor walks it to produce `TableRef[]` and `ColumnLineage[]`
- Dialect differences handled at tokenizer level (e.g., backtick vs double-quote identifiers, BigQuery dataset.table syntax)

### `src/core/dbt/` — dbt Project Provider

Parses dbt project structure directly from files. No Python bridge, no manifest.json required.

**Capabilities:**
- Parse `dbt_project.yml` for project config (name, model paths, source paths, etc.)
- Parse `schema.yml` / `sources.yml` for source definitions, model descriptions, column descriptions, tests
- Parse model SQL files for `{{ ref('model_name') }}` and `{{ source('source', 'table') }}` references
- Resolve ref/source to actual file paths
- Build model dependency graph from ref/source analysis
- Read `manifest.json` and `catalog.json` when available (for enhanced metadata)
- Support dbt Fusion project structure
- File watcher for live updates on save

**Jinja handling:**
- Subset parser for `ref()`, `source()`, `config()`, `var()`, `env_var()`
- Does NOT attempt full Jinja template rendering (that requires dbt itself)
- Strips Jinja blocks/expressions for SQL parsing (passes cleaned SQL to SQL parser)

### `src/core/lineage/` — Lineage Engine

The abstraction layer that unifies lineage from multiple providers.

```typescript
interface LineageProvider {
  id: string;
  name: string;

  /** Discover all models/tables in this provider's scope */
  discover(): Promise<LineageNode[]>;

  /** Get direct dependencies for a node */
  dependencies(nodeId: string): Promise<string[]>;

  /** Get column-level lineage for a node */
  columnLineage?(nodeId: string): Promise<ColumnLineage[]>;

  /** Watch for changes */
  onDidChange: vscode.Event<LineageChangeEvent>;
}

interface LineageNode {
  id: string;
  name: string;
  type: 'model' | 'source' | 'seed' | 'snapshot' | 'test' | 'exposure' | 'table' | 'view';
  provider: string;
  filePath?: string;
  description?: string;
  columns?: ColumnInfo[];
  tags?: string[];
  materialization?: string;
}
```

**Providers:**
- `DbtLineageProvider` — Uses dbt project parser
- `SqlLineageProvider` — Uses SQL AST parser on raw .sql files (SQLMesh-style)
- Future: `ManifestLineageProvider` — Reads pre-built manifest.json for fast startup

### `src/extension/` — VSCode Extension Shell

Thin integration layer that connects core libraries to VSCode APIs.

**Components:**
- Language registration (Jinja-SQL grammar, language configuration)
- Completion provider (models, sources, macros, columns)
- Definition provider (go-to-definition for refs, sources, macros)
- Hover provider (model metadata, column descriptions)
- Code lens provider (run model, test model)
- Document link provider (clickable ref/source links)
- Tree view providers (model explorer, lineage tree)
- Status bar items (project name, active model info)
- Command registrations (run dbt, open lineage, open docs)
- Webview panel management

**dbt Command Execution:**
```typescript
class DbtCli {
  constructor(private dbtPath: string) {}

  async run(args: string[], cwd: string): Promise<DbtResult> {
    return new Promise((resolve, reject) => {
      const proc = spawn(this.dbtPath, [...args, '--log-format', 'json'], { cwd });
      // Stream stdout/stderr, parse JSON log lines
    });
  }
}
```

### `src/webview/` — React Webview Panels

Modern React-based panels communicating via `postMessage`.

**Lineage Graph Panel:**
- Canvas-based rendering (HTML5 Canvas or WebGL via a library like `@pixi/react` or raw Canvas2D)
- Not DOM-based — handles thousands of nodes without DOM overhead
- Layout: Dagre or ELK for automatic DAG layout
- Interactions:
  - Click node → highlight, show details
  - Double-click → open file
  - Right-click → context menu (run, test, show upstream/downstream)
  - Click + drag → pan
  - Scroll → zoom
  - Select two nodes → highlight all paths between them
  - Expand/collapse upstream/downstream on demand
  - Filter by: tag, folder, materialization, resource type
  - Mini-map for large graphs
- Prepared for editor mode:
  - Drag from node to node → create ref
  - Delete edge → remove ref
  - Drag file from explorer → add to graph
  - These operations generate SQL/YAML edits in the text editor

**Instant Docs Panel:**
- Renders documentation from YAML descriptions + SQL comments
- No manifest.json build required
- Shows: model description, column descriptions, tags, tests, dependencies
- Live updates as files change
- Search across all models

**Query Results Panel:**
- Tabular data display
- Sort, filter columns
- Export to CSV
- Basic charting

## Comparison with Power User

| Aspect | Power User | DVT |
|---|---|---|
| Extension dependencies | 3 required | 0 required |
| SQL parsing | Python (sqlglot via bridge) | TypeScript (native) + optional CLI |
| dbt execution | Python bridge (in-process dbtRunner) | CLI subprocess (no Python ext needed) |
| Syntax highlighting | Depends on jinjahtml extension | Bundled TextMate grammar |
| AI features | Altimate SaaS (proprietary) | None (standalone) |
| Lineage source | manifest.json + Altimate API | SQL AST + dbt project files (manifest optional) |
| Lineage abstraction | dbt-only | SQL-first (dbt is one provider) |
| Graph rendering | DOM-based React | Canvas-based (performant at scale) |
| IoC framework | Inversify (heavyweight) | Simple module wiring |
| Column lineage | Server-side (Altimate API) | Client-side (SQL AST analysis) |
