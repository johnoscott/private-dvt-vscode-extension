# Research: vscode-dbt-power-user (AltimateAI)

## External Extension Dependencies

The existing extension has **3 hard extension dependencies** (`extensionDependencies` in package.json):

1. **`samuelcolvin.jinjahtml`** — Provides Jinja-SQL/YAML/Markdown syntax highlighting (TextMate grammars for `jinja-sql`, `jinja-yaml`, `jinja-md`)
2. **`ms-python.python`** — Microsoft Python extension, required because the extension communicates with dbt through `python-bridge` (imports dbtRunner in-process or runs CLI subprocess)
3. **`altimateai.vscode-altimate-mcp-server`** — AltimateAI's closed-source companion MCP server extension (not publicly available on GitHub)

### Runtime / System Dependencies

- Python environment with dbt Core >= 1.0 installed
- Optional: `altimate-datapilot-cli` (closed-source pip package, auto-installed by extension)
- Optional: Altimate AI account (API key + instance name) for AI features

### Key npm Dependencies

- `@altimateai/dbt-integration` (MIT) — Core dbt project detection, parsing, command execution, HTTP client for Altimate API. Depends on `@altimateai/altimate-core`.
- `python-bridge` — Node-to-Python IPC bridge for running dbt in-process
- `inversify` — Dependency injection framework
- `zeromq` + Jupyter packages — For notebook/kernel support
- Bundled `sqlglot` Python package (vendored) for SQL parsing/dialect translation

## Feature Inventory

### Core IDE Features (no Altimate account needed)

- Auto-completion for model names, macros, sources, docs
- Go-to-definition for models, macros, sources, docs
- Hover information for models, macros, sources
- Live compiled SQL preview (as you type)
- Code lenses for generating models from source YAML
- dbt run/build/test execution from the editor
- SQL formatting (via sqlfmt)
- Jinja-SQL/YAML/Markdown snippets
- DAG depth calculation and tree views (parent/children models, tests, documentation)
- Defer to production (reference production manifests)
- dbt log viewer with force tailing
- Run history tracking
- Query results panel with Perspective.js visualization (graphs, filters, groups, CSV export)
- BigQuery cost estimation
- Support for dbt Core, dbt Cloud, and Fusion integration modes

## Architecture Analysis

### Activation
Activates when `**/dbt_project.yml` is found in workspace.

### Dependency Injection
Uses **Inversify** IoC container extensively. Nearly all services, providers, and panels are registered as injectable classes in a single large config file.

### Entry Point Flow
1. `extension.ts` → gets `DBTPowerUserExtension` from IoC container → calls `activate()`
2. `DBTPowerUserExtension` orchestrates ~17 subsystems as disposables:
   - `DBTProjectContainer` — project detection, manifest parsing, workspace management
   - `WebviewViewProviders` — lineage, docs editor, query results, insights, DataPilot chat
   - `AutocompletionProviders` — model, macro, source, doc autocompletion
   - `DefinitionProviders` — go-to-definition
   - `HoverProviders` — hover info
   - `CodeLensProviders` — inline actions
   - `ContentProviders` — SQL preview content
   - `DocumentFormattingEditProviders` — sqlfmt integration
   - `TreeviewProviders` — sidebar tree views
   - `StatusBars` — version, defer-to-production status
   - `VSCodeCommands` — command registrations
   - `CommentProviders` — conversation threads
   - `ValidationProvider` — SQL validation
   - `NotebookProviders` — Jupyter-based notebooks
   - `DbtPowerUserMcpServer` — MCP server for AI agent integration
   - `TelemetryService` — telemetry

### Python Bridge
Communicates with dbt through `python-bridge`, executing dbt commands in user's Python environment. Supports `PythonDBTCommandExecutionStrategy` (importing dbtRunner in-process) and `CLIDBTCommandExecutionStrategy` (CLI subprocess).

### Manifest Parsing
Parses dbt's `manifest.json`, `catalog.json`, and project YAML files through dedicated parsers (`graphParser`, `nodeParser`, `sourceParser`, `macroParser`, `docParser`, `testParser`, `exposureParser`, `metricParser`). File watchers track changes.

### Webview Panels
React-based panels using message-passing between extension host and webview. Key panels: lineage visualization, documentation editor, query results (Perspective.js), DataPilot chat, insights/actions.
